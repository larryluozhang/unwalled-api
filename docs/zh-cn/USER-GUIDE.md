# Unwalled API 使用说明（产品化版）

> 版本：随 che 分支发版持续更新。每完成一个特性/修复，必须同步更新本文件。
> 目标读者：产品用户（非开发者）。所有功能以"实际怎么用"为准，不是"代码里有什么"。

## 1. 这是什么

Unwalled API 是一个自托管的 LLM 网关：把你手里各家（免费/付费）的 API key 集中到一个 OpenAI 兼容端点 `/v1`，由路由器按可靠性、速度、智能、配额自动挑模型，失败自动换下一家。支持对话、嵌入、重排、生图、语音。

## 2. 核心概念（先懂这三个）

### 2.1 回退链（Fallback Chain）
一条链 = 一组模型按顺序排列。请求来了先找第一个，失败（超时/报错/限流）自动跳到下一个。链可以在 `/v1/models` 里用 `auto:<链名>` 调用（比如 `auto:cc-main`）。

### 2.2 路由策略（Routing Strategy）
决定"顺序怎么来"：
- **手动（priority）**：顺序完全由你指定（拖拽排序）。**想手动钉死顺序，必须选它**
- 均衡（balanced）：可靠性×速度×智能混合打分，老虎机自动探索（默认）
- 最智能（smartest）/ 最快（fastest）/ 最稳定（reliable）/ 自定义（custom）

### 2.3 命名链（Profile）
自定义的链（比如 cc-main、cc-classifier、memos-judge），可设专属时间预算和策略。以 `auto:<链名>` 寻址。

### 2.4 账号选择（key selection，che.41 起）
当同一家提供商配了多个 key，路由选完模型后再选账号：
- **自动**：保持现有老虎机/轮换（默认，推荐共享账号池用）
- **按剩余额度**：优先剩余额度最多的 key
- **Smart**：优先最快到期的额度，适合愿意"临期用掉"的免费/低频额度
- **Pace**：按可比配额的重置周期分配消耗，适合周期性配额

注意：账号选择只改同一模型下 key 的尝试顺序，**不改变模型质量排序**；健康、冷却、scope、token、并发等限制始终优先。不建议给昂贵的付费链盲开 Smart/Pace。

### 2.5 缓存粘性（cache affinity，che.41 起）
命名 profile 可设 `cache_stickiness_mode`（默认 `legacy`）。设为 `cache` 后：如果上一请求真实命中了至少 1024 个缓存 token，同一会话且前缀/工具一致时，会软偏好上次答 key，提升缓存命中率。它不是精确缓存复用；冷却/不可用/配额尽/前缀变化时仍可换 key，Default 与 `cc-main` 默认不启用。

### 2.6 三个策略开关的图形界面（che.42 起）
以上三个策略——**排序策略**（routing_strategy）、**账号选择**（key_selection_strategy）、**缓存粘性**（cache_stickiness_mode）——现在都能在「回退链」管理器里每条链对应行直接配置：
- 三个下拉选项均已中文化（英文版界面显示对应英文），鼠标悬停任一选项会弹出**含义备注**，说明每种取值的行为和适用场景，方便正确选择。
- 缓存粘性此前只能改数据库，现已补上图开关：关（默认）/ 同会话粘 key。
- 三个开关都是 **opt-in**：默认链、付费 `cc-main` 不开启，不改变现有行为。建议先在测试链验证再推广。

## 3. 模型与回退链页（最常用的页面）

### 3.1 手动调整调用顺序（拖拽排序）

**前置条件（缺一不可，2026-10-25 实测）**：
1. **全局路由策略 = 手动**：在"模型"页顶部的"路由策略"卡片（显示"可靠性35% · 速度10% · 智能55%"那个区域），点 **「手动」** 按钮。注意：链条上的策略下拉只是 profile 覆盖，不影响拖拽开关——真正控制拖拽的是这个全局"手动"按钮。
2. **没有激活筛选**：搜索框为空、"视觉"/"工具"/上下文筛选全部关闭。
3. **"只看开启"开关关闭**：开着会禁用拖拽（防止你只拖可见子集把隐藏成员顺序搞乱）。

**操作**：
1. 满足上面三条后，行首会出现拖拽手柄（"拖动以重新排序模型"按钮）
2. 按住手柄上下拖到目标位置
3. 底部浮出"保存修改"→ 点击保存（顺序写入后端）

**注意**：
- 命名链（profile）与 Default 链共享同一个"手动"开关；profile 专属策略只影响路由计算，不影响拖拽可用性
- 切到手动后，排第一的模型失败才会跳下一个——它不会"自动绕开慢的"，这是手动控制的代价

### 3.2 "只看开启"开关
默认开启（只显示启用的模型）。**要拖拽排序必须先关掉它**（见 3.1）。

### 3.3 成员优先级
不用填数字：拖拽后后端自动按你拖的顺序赋 priority 值（1,2,3…）。

## 4. 分析页

### 4.1 最近调用
- 时间段四档：24h / 7d / 30d / 90d
- **加载更多**：che.36 起支持翻页（每页 500 条），底部按钮显示"还有 N 条"
- 筛选：状态（成功/失败/取消）、提供方
- 明细受保留行数限制（`REQUEST_ANALYTICS_MAX_ROWS`，默认 10 万行）；图表走聚合表不受限

### 4.2 常见客户端 UA 对照
- `OpenAI/Python x.x.x`：MemOS 等 Python 客户端
- `claude-cli/x.x.x`：Claude Code（VS Code 插件/独立 CLI）
- `node`：网关自己的每日审计容器（凌晨 5:17 例行探测，不是业务调用）

## 5. 设置页

### 5.1 每日模型审计开关（che.38 起）

位置：设置 → **审计**（在“常规”旁）。

- **执行每日审计**：总开关。关闭后，下一次定时模型发现/探测和签名 feed 导出都会停止。
- **按平台审计**：可单独启停某个平台；付费/混合平台（当前为 SiliconFlow 国际站/国内站）默认关闭，只有人工明确开启才会探测。
- 保存即时生效于配置，但实际执行在下一次定时运行（通常东八区 05:17）；切换不会立即发起探测。
- 这些开关**不影响正常业务路由、提供方密钥、已启用模型或已有 feed 内容**。想关闭某个平台的日常探测，不必停用它的业务模型。

### 5.2 版本与更新检查（che.36 起）
- "当前构建"版本号随 git tag 自动更新（不再停尸旧版本）
- 更新检查的基准分支可配（`FREELLMAPI_UPDATE_BASE_BRANCH`），146 已设 `che`——不再误报"无法与官方 main 分支比较"

## 6. 高级：服务端分类器（che.37 起）

当客户端（Claude Code auto 模式）在请求里带 `safeguards` 字段时，网关在响应里回 `safeguard_results`（本地判定的 verdict）。效果：
- 客户端不再弹"this session isn't eligible"计费提示
- 危险命令（rm -rf / 等）被 deny，正常命令放行
- 客户端不再回退烧主模型做权限分类

**注意**：本地判定器是启发式（危险命令清单），后续会接 cc-classifier 链跑真实分类 prompt（协议管道已通）。

## 6.5 客户端协议适配：Anthropic 与智能体子页

「密钥」页除了"提供方 / 配额信号 / 统一 API 密钥"外，还有两个子页——**Anthropic** 和 **智能体（Agents）**。它们是给"用 Anthropic/Gemini 原生协议、或只认特定模型名的客户端"做的适配层。日常用 OpenAI 兼容端点 + `auto:<链名>` 已经够，所以可能一直没碰过。

### 6.5.1 Anthropic 子页：Claude 模型映射

**配什么**：Claude 客户端（Claude Code、Anthropic SDK）只认 `claude-opus-*`/`claude-sonnet-*` 这种名字，不知道池子里是 Gemini/Groq/免费模型。这个映射表告诉网关"客户端要 `claude-sonnet` 时实际路由到哪"。

- **默认 / Opus / Sonnet / Haiku** 四档，每档可填：
  - `auto`（默认）：路由器在 Default 链里挑
  - **具体模型 id**（如 `kimi-for-coding`）：把这个槽钉死到该模型
  - **`auto:<链名>`**（che.42 起）：把整族路由到指定回退链（见下）
- 页面同时给出连接参数：基础 URL `http://<主机>:3001`、鉴权头 `x-api-key`

**案例 A：Sonnet 槽固定走 kimi-for-coding**
> Sonnet 槽填 `kimi-for-coding`。之后任何 Claude Code 发 `claude-sonnet-4-5`，网关都路由到 kimi-for-coding 模型，Opus/Haiku 不受影响。

**案例 B（che.42 新增）：Sonnet 槽走 cc-main 链，全主机免改配置**
> Sonnet 槽填 `auto:cc-main`，分类器（Haiku）槽填 `auto:cc-classifier`。
>
> **效果**：各主机的 Claude Code **只要发内置的 `claude-sonnet-*`/`claude-haiku-*`**（它们的出厂默认），网关就统一按子页映射路由到 cc-main / cc-classifier 链。**不用再到每台主机上单独改 `ANTHROPIC_MODEL` 或模型映射**——集中在一处（子页）配置，全主机生效。
>
> 此前（che.41 及更早）子页只认 `auto`/具体模型 id，填 `auto:cc-main` 会被当成模型名查不到、静默退回 Default 链。che.42 补齐了这条路径。

### 6.5.2 智能体（Agents）子页：三块配置

1. **Gemini 模型映射**：同 Anthropic 那个，针对 Gemini SDK 客户端（`gemini-pro`/`gemini-flash`/`gemini-flash-lite` → auto 或钉死）。
2. **智能体兼容性**：
   - **Ollama 模拟**（默认 off）：让网关假装成 Ollama，给只支持 Ollama 的客户端用
   - **Claude Code 发现别名**：开放 `claude/<model>` 别名，让 Claude Code 的模型选择器能列出目录模型
   - **MCP 服务器**（默认关）：向智能体客户端开放 `/mcp` 端点
3. **可撤销的 URL 令牌**：给**不能发自定义请求头**的客户端——把 API key 编进 URL。安全性较弱（会进历史记录/日志），不再需要时请及时撤销。

## 6.6 本地隐私脱敏（v1.2.1 起）

把提示词里的**密钥和个人隐私数据**在发给上游之前打码成占位符，上游回复时再把占位符还原成原值——上游模型永远看不到你的真实隐私，而你看到的回答仍是原文。

**图形开关**（v1.2.3 起）：设置 → **隐私** 子页，三个开关——「启用隐私脱敏」（总开关，默认开）、「脱敏密钥」、「脱敏个人数据」，各配含义备注。改完即时生效，免重启。

也可用 settings 表 / env 手动控制：
- `redact_enabled`：总开关。settings 表写入 `'1'`/`'0'`，或 env `REDACT_ENABLED`。
- `redact_secrets`：密钥类（API key / token / password / 私钥 / JWT / Bearer）。
- `redact_personal`：个人数据类（邮箱 / 手机号 / 身份证 / 银行卡 / ssh user@host）。

**覆盖范围**：四个推理面（`/v1/chat/completions`、`/v1/responses`、`/v1/messages`、inbound-chat）统一在 provider 层挂钩，提示词的文本块、工具调用参数、思考链（reasoning）都会脱敏；非流式与流式响应都还原（含跨 chunk 拼接的占位符）。

**会脱敏的**：
- 密钥：`sk-...`、`AIza...`、`ghp_...`、`AKIA...`、`api_key=...`、`password=...`、Bearer token、私钥头、JWT
- 个人数据：邮箱、11 位手机号、18 位身份证、Luhn 校验通过的银行卡号、ssh/scp 的 user@host

**不会误伤的**（这些保持原样）：
- 订单号 / 用户 id / 编号等**形如手机号的数字**（`订单号 13912345678` 不掩，`我的手机号 13800138000` 掩）
- UUID、32 位 hex（request/session/commit id）——模型要原样读回，掩了工具调用就查不到
- 工具调用的 `id`/`name`、`image_url`、`signature`/`encrypted_content` 等结构字段

**可逆映射**：同一个值在任何请求里都是同一个占位符（HMAC keyed hash），所以缓存前缀仍有效、思考链签名仍匹配；值只存内存（有界），重启后下次请求自动重新带入。

**注意**：本版是**规则层**（正则 + 字段名感知），覆盖密钥和常见 PII。中文姓名/地址这类需要 NER 模型的识别留待后续版本。脱敏默认不影响 Default 链与付费 cc-main——需你显式开启。

## 7. 已知坑（持续补充）

- **拖拽不动？** 先看 3.1 的三条前置条件（全局手动 / 无筛选 / 关只看开启），最容易漏的是"全局手动"和"只看开启"
- **更新检查误报 main 分支？** che.36 已修（基准分支可配 che）
- **分类器调用跑哪了？** 看客户端 UA + requested_model，不要只看"google 出现"就断定（Default 链也有 google）
- **node UA 大量调用？** 是每日审计容器（05:17 例行），不是 MemOS 任务
- **回退链顺序"自动变化"？** 你用的是打分策略（balanced 等）会自动漂移；要钉死顺序必须切"手动"（见 3.1）
