# Unwalled API 使用说明（产品化版）

> 版本：随 che 分支发版持续更新。每完成一个特性/修复，必须同步更新本文件。
> 目标读者：产品用户（非开发者）。所有功能以"实际怎么用"为准，不是"代码里有什么"。

## 1. 这是什么

Unwalled API 是一个自托管的 LLM 网关：把你手里各家（免费/付费）的 API key 集中到一个 OpenAI 兼容端点 `/v1`，由路由器按可靠性、速度、智能、配额自动挑模型，失败自动换下一家。支持对话、嵌入、重排、生图、语音。

## 2. 核心概念（先懂这三个）

### 2.1 回退链（Fallback Chain）
一条链 = 一组模型按顺序排列。请求来了先找第一个，失败（超时/报错/限流）自动跳到下一个。链可以在 `/v1/models` 里用 `auto:<链名>` 调用（比如 `auto:cc-main`）。

### 2.2 路由策略（Routing Strategy）
决定"顺序怎么来"：
- **手动（priority）**：顺序完全由你指定（拖拽排序）。**想手动钉死顺序，必须选它**
- 均衡（balanced）：可靠性×速度×智能混合打分，老虎机自动探索（默认）
- 最智能（smartest）/ 最快（fastest）/ 最稳定（reliable）/ 自定义（custom）

### 2.3 命名链（Profile）
自定义的链（比如 cc-main、cc-classifier、memos-judge），可设专属时间预算和策略。以 `auto:<链名>` 寻址。

## 3. 模型与回退链页（最常用的页面）

### 3.1 手动调整调用顺序（拖拽排序）

**前置条件（缺一不可，2026-10-25 实测）**：
1. **全局路由策略 = 手动**：在"模型"页顶部的"路由策略"卡片（显示"可靠性35% · 速度10% · 智能55%"那个区域），点 **「手动」** 按钮。注意：链条上的策略下拉只是 profile 覆盖，不影响拖拽开关——真正控制拖拽的是这个全局"手动"按钮。
2. **没有激活筛选**：搜索框为空、"视觉"/"工具"/上下文筛选全部关闭。
3. **"只看开启"开关关闭**：开着会禁用拖拽（防止你只拖可见子集把隐藏成员顺序搞乱）。

**操作**：
1. 满足上面三条后，行首会出现拖拽手柄（"拖动以重新排序模型"按钮）
2. 按住手柄上下拖到目标位置
3. 底部浮出"保存修改"→ 点击保存（顺序写入后端）

**注意**：
- 命名链（profile）与 Default 链共享同一个"手动"开关；profile 专属策略只影响路由计算，不影响拖拽可用性
- 切到手动后，排第一的模型失败才会跳下一个——它不会"自动绕开慢的"，这是手动控制的代价

### 3.2 "只看开启"开关
默认开启（只显示启用的模型）。**要拖拽排序必须先关掉它**（见 3.1）。

### 3.3 成员优先级
不用填数字：拖拽后后端自动按你拖的顺序赋 priority 值（1,2,3…）。

## 4. 分析页

### 4.1 最近调用
- 时间段四档：24h / 7d / 30d / 90d
- **加载更多**：che.36 起支持翻页（每页 500 条），底部按钮显示"还有 N 条"
- 筛选：状态（成功/失败/取消）、提供方
- 明细受保留行数限制（`REQUEST_ANALYTICS_MAX_ROWS`，默认 10 万行）；图表走聚合表不受限

### 4.2 常见客户端 UA 对照
- `OpenAI/Python x.x.x`：MemOS 等 Python 客户端
- `claude-cli/x.x.x`：Claude Code（VS Code 插件/独立 CLI）
- `node`：网关自己的每日审计容器（凌晨 5:17 例行探测，不是业务调用）

## 5. 设置页

### 5.1 每日模型审计开关（che.38 起）

位置：设置 → **审计**（在“常规”旁）。

- **执行每日审计**：总开关。关闭后，下一次定时模型发现/探测和签名 feed 导出都会停止。
- **按平台审计**：可单独启停某个平台；付费/混合平台（当前为 SiliconFlow 国际站/国内站）默认关闭，只有人工明确开启才会探测。
- 保存即时生效于配置，但实际执行在下一次定时运行（通常东八区 05:17）；切换不会立即发起探测。
- 这些开关**不影响正常业务路由、提供方密钥、已启用模型或已有 feed 内容**。想关闭某个平台的日常探测，不必停用它的业务模型。

### 5.2 版本与更新检查（che.36 起）
- "当前构建"版本号随 git tag 自动更新（不再停尸旧版本）
- 更新检查的基准分支可配（`FREELLMAPI_UPDATE_BASE_BRANCH`），146 已设 `che`——不再误报"无法与官方 main 分支比较"

## 6. 高级：服务端分类器（che.37 起）

当客户端（Claude Code auto 模式）在请求里带 `safeguards` 字段时，网关在响应里回 `safeguard_results`（本地判定的 verdict）。效果：
- 客户端不再弹"this session isn't eligible"计费提示
- 危险命令（rm -rf / 等）被 deny，正常命令放行
- 客户端不再回退烧主模型做权限分类

**注意**：本地判定器是启发式（危险命令清单），后续会接 cc-classifier 链跑真实分类 prompt（协议管道已通）。

## 7. 已知坑（持续补充）

- **拖拽不动？** 先看 3.1 的三条前置条件（全局手动 / 无筛选 / 关只看开启），最容易漏的是"全局手动"和"只看开启"
- **更新检查误报 main 分支？** che.36 已修（基准分支可配 che）
- **分类器调用跑哪了？** 看客户端 UA + requested_model，不要只看"google 出现"就断定（Default 链也有 google）
- **node UA 大量调用？** 是每日审计容器（05:17 例行），不是 MemOS 任务
- **回退链顺序"自动变化"？** 你用的是打分策略（balanced 等）会自动漂移；要钉死顺序必须切"手动"（见 3.1）
